# AI 游戏后端套件方案

> 版本：v0.1（方案稿）
> 日期：2026-08-11
> 状态：已吸收进开发计划（见 `docs/development-plan.md`），Phase 1 可直接开工

---

## 一、背景与目标

### 1.1 现状

- 正在开发与计划中的 **AI 接入游戏有多款**，形态为**网页游戏**：玩家点开即玩，公测，无登录体系。首发场景为《文明史诗》的 NPC AI 对话。
- 希望将一些 API 额度以"玩家免费额度"的形式发放，作为游戏功能的一部分。

### 1.2 目标

搭建一套**通用 AI 游戏后端套件**：

1. 多款游戏共用一个中心服务，新游戏接入零新增代码、只加配置；
2. 玩家零门槛（无注册、无登录），打开网页即可使用 AI 功能；
3. 额度发放可控：每玩家每日免费额度 + 兑换码加量，全局成本有硬顶；

```
            │                        └───────┬───────────┬─────────┘

```

## 三、核心组件

### 3.1 AI 套件服务（单部署单元）

一个服务进程，配置驱动，包含全部网关逻辑：

**多游戏配置**

- 请求携带 `game_id`，服务端按 id 加载配置：prompt 模板、模型选择、限流档位、降级文案；
- 游戏身份不靠密钥（网页前端藏不住任何东西），配置选择器 + 服务端校验即可；
- 新游戏接入 = 在配置文件里加一个条目。

**玩家会话与额度**

- 匿名会话：首次请求种 cookie 发会话令牌，玩家全程无感；
- 每会话每日免费额度（即"发给玩家的那批额度"，按游戏可配）；
- 兑换码表：玩家输码加额度，用于活动、老玩家回馈；
- 额度记录用 SQLite 起步，量上来再换。

**防护体系（公网免费发放 LLM 推理的必备底线）**

| 层 | 机制 | 作用 |
|---|---|---|
| 人机验证 | Cloudflare Turnstile（首次发起 AI 对话时触发） | 挡脚本批量刷量，玩家基本无感 |
| 每 IP 限流 | 如每分钟 N 次 | 防单点滥用 |
| 每会话限流 | 每日额度硬上限 | 单个玩家损失封顶 |
| 全局熔断 | 每日总预算硬顶，耗尽即停 | 假设前两层全被绕过，日损失仍封顶 |
| 降级兜底 | 熔断后 报错 | 游戏不可玩，我们是AI原生游戏 |

**关键认知**：客户端内任何凭证都可被提取，防线全部在服务端；额度上限的意义是让任何泄露的损失封顶在几块钱。

### 3.2 前端 SDK

- 极轻量：fetch 封装 + SSE 流式接收 + 会话管理 + Turnstile 集成；
- 新游戏接入 = 引入一个文件 + 配置 `game_id`。

### 3.3 游戏服务端转发层（可选）

- 若某游戏已有自己的服务端，可经其转发到套件服务（该游戏可做自己的业务校验）；
- 纯静态网页游戏则前端直连套件服务，防护依赖套件自身的会话 + Turnstile + 限流体系。
